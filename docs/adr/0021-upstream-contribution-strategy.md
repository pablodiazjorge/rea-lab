# How the lab contributes to rea

Status: accepted, amended in F4

Claim the issue with a short proposal (open one first when none exists) and start the work right away on a local branch: rea merges most pull requests within hours, so waiting days for an answer means someone else fixes it first. Open the pull request only once it is complete: minimal, with tests, the full template, only commands that were actually run and evidence from real Windows. If the maintainer narrows or rejects the proposal meanwhile, adapt or drop the branch. Keep one pull request open at a time. A pull request closed as superseded with credit counts as a success, and non-code contributions (Windows lane reports, measurements) come first, because the lab's advantage is a Windows machine where rea works.

# The benchmark reuses rea's evaluation where it fits

Status: proposed (F4), to be accepted after the pilot

Answers use rea's closed claims manifest, one JSON object and nothing else: `{"claims": [{"id", "value", "evidence_id", "confidence", "authority"}]}`. Condition A has no Evidence, so its manifest is the same without `evidence_id`. rea 6.4.0 passes a claim only when its value appears literally in the cited Evidence, which does not fit a crackme whose answer is computed (an XOR-decoded string, an input that satisfies a checksum), so values are graded by the challenge oracle (`challenges/oracle.mjs`). From rea the benchmark reuses two pieces. `parseEvidence` authenticates every Evidence delivered in the transcript, which decides whether each cited `evidence_id` is real and about the target (rea's `unknown_evidence`, `conflicting_evidence` and subject checks). `evaluateCodexEvents` provides the tool-usage metrics with rea's exact definitions (natural use, first tool, repeated calls, input validation failures, the `open_binary` to `close_binary` subsequence), fed by an adapter that turns Claude Code's stream-json into the Codex-shaped events it reads. Claude Code delivers MCP results as text, so the adapter accepts an Evidence only from a single text block that parses as closed JSON, the rule rea added upstream after 6.4.0. Metrics that rea does not have (wall time, turns, cost, every tool call by name, permission denials, timeouts) come from the benchmark itself.

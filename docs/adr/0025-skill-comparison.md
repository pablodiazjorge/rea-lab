# Skill comparison: the skill's content, injected

Status: proposed (study 5)

Study 5 compares rea's own skill with an improved version, both with Claude Code and `claude-sonnet-5-5`, on real-software tasks ([ADR 0024](0024-real-software-tasks.md)). In study 1 the skill was copied into the run's configuration folder, as `rea setup` does, and the agent never loaded it in any of the 10 runs that offered it, so its content has never been measured. Study 5 therefore measures the content, not whether the client decides to load it: the body of `SKILL.md` goes into the system prompt with Claude Code's `--append-system-prompt-file`, after one fixed sentence that says what it is and is the same for every skill. Its `references/` files are copied into the run's configuration folder and are readable, so the agent opens them on demand as it would with an installed skill. The writeup states this scope.

There are three conditions, all with rea over MCP and the same prompt, tools and limits as condition B of study 3: B without a skill, C1 with rea's official skill from the pinned rea 6.4.0, and C2 with the improved skill. H1 compares C2 with C1 and H2 compares C1 with B, each on two co-primary outcomes. The first is the cost per run: an exact Wilcoxon signed-rank test on each task's log ratio of mean costs, with the Hodges-Lehmann ratio and its exact interval. The second is whether the Evidence cited for the answer states the answered address: an exact McNemar test on runs paired by task and repetition. Holm's method adjusts the two outcomes of each hypothesis together. A power simulation on study 3's costs showed that 20 tasks would detect a cost cut of 30 % but miss most cuts under 20 %, so the study uses more tasks rather than more repetitions. Accuracy is at the ceiling on these programs, so it is reported as a guardrail, not tested.

The improved skill is a revised copy of the official one, kept in `bench/skills/` with rea's MIT copyright notice and a provenance note. It keeps the official structure and a similar length, because a shorter skill would lower input tokens by construction: each skill's SHA-256 and size in bytes are locked with the study, the input tokens of each run's first request are measured from the transcripts, and cost is reported together with tokens of each type, turns and rea calls. Runs of one condition share a cached prompt prefix, so the first request's cache writes depend on the run order; a sensitivity analysis prices them as cache reads, at the list prices Claude Code uses for its equivalent cost; each run records its first request's usage for it. Its changes come from the transcripts of earlier studies, from public pilot tasks and from published guidance, and its provenance note names the source of each one. It names only tools present both in rea 6.4.0 and in rea's current main branch, nothing specific to one client and nothing about the studies' programs or published targets, which a test checks. It is frozen in a commit, with its SHA-256, before the study's tasks are drawn ([ADR 0011](0011-reproducible-challenges.md)), so it cannot be tuned to them. If it wins, its native section is proposed to rea as a small addition to the current skill.

Known limitations: injecting the skill is not how an agent meets it in normal use, and one client and one model say nothing about others.
